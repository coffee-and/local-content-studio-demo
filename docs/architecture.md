# 기술 설계 요약

## 계층 분리

1. `ui/`: 화면과 사용자 이벤트
2. `services/`: 콘텐츠 생성, 이미지 처리, 저장, 일괄 처리, 스케줄 실행
3. `database.py`: SQLite 접근과 트랜잭션
4. `models.py`: UI와 서비스 사이 요청·결과 데이터

## 콘텐츠 생성 흐름

```text
사용자 입력 또는 스케줄
→ 프롬프트 + 지역 + 키워드 조합
→ OpenAI API 또는 Mock 생성
→ 제목·본문 정규화 및 SHA-256
→ 최근 생성 이력과 유사도 비교
→ 중복이면 1회 다른 관점으로 재시도
→ SQLite 기록
→ 날짜/지역/키워드 폴더에 TXT·MD·JSON 저장
```

## 이미지 처리 흐름

```text
이미지 읽기(한글 경로 지원)
→ 얼굴/번호판 보조 검출 또는 수동 ROI
→ ROI 좌표 보정
→ 픽셀 모자이크 또는 가우시안 블러
→ 원본은 그대로 유지
→ 결과 이미지 별도 저장
→ SQLite에 원본·결과 경로, 처리 방식, ROI 개수 기록
```

## 스레드 정책

- OpenAI 네트워크 요청: Qt `QThreadPool` 작업
- 폴더 일괄 이미지 처리: Qt `QThreadPool` 작업
- UI 변경: 메인 스레드의 Signal/Slot에서 처리
- 단일 이미지 미리보기: 빠른 로컬 연산이라 UI 이벤트에서 처리

## 스케줄 정책

- 스케줄 정의와 다음 실행 시각은 SQLite에 저장
- QTimer가 일정 간격으로 만료된 스케줄을 원자적으로 claim
- claim 시 다음 실행 시각을 먼저 갱신해 중복 실행 방지
- 실제 운영에서 앱 종료 상태 실행이 필요하면 Windows Task Scheduler 또는 서비스 방식으로 확장

## 중복 방지 정책

- 정규화한 제목·본문 SHA-256 완전 중복 검사
- 최근 성공 콘텐츠 200건과 `SequenceMatcher` 유사도 비교
- 제목 70%, 본문 30% 가중치
- 설정 탭에서 임계값 변경 가능

## 확장 지점

- 한국 번호판 전용 검출기
- 얼굴 검출 DNN 또는 YOLO 계열 모델
- Windows 서비스/작업 스케줄러 등록
- 암호화된 API 키 저장소
- 콘텐츠 품질 규칙 엔진
- 복수 사용자·권한·중앙 서버
